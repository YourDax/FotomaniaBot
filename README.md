# MAX Рассылки

> **English summary.** A local web app for managing school-photography clients and preparing manual mailings: FastAPI + SQLAlchemy + SQLite backend, CSV/XLSX import with column mapping and duplicate handling, a background job queue, and an operator UI (vanilla JS ES modules). Message text is prepared in an already-signed-in browser tab via Playwright/CDP; sending is always confirmed by the operator. Tests: pytest; linting: ruff.

Локальное приложение для управления клиентами и подготовки ручных рассылок через уже авторизованный интерфейс MAX. Данные остаются в SQLite на компьютере оператора.

## Важное ограничение MAX

Проект не использует API MAX, не извлекает сессии и не создаёт новую авторизацию. В ручном режиме кнопка «Подготовить в MAX» подключается Playwright к уже запущенному Chromium через CDP, находит клиента в открытой авторизованной вкладке, проверяет открытие чата и вставляет подготовленный текст. Кнопка «Открыть чат» выполняет только поиск по номеру и открывает найденный диалог, не вставляя текст. Кнопка отправки **никогда не нажимается автоматически**: отправку и её результат подтверждает оператор.

При подготовке сообщения приложение проверяет CDP на `MAX_CDP_URL` (по умолчанию `http://127.0.0.1:9222`). Если endpoint не найден, оно само запускает установленный Chromium с постоянным профилем `browser-profile` в каталоге данных (см. ниже) и открывает MAX. Для уже авторизованной сессии можно задать `MAX_BROWSER_PROFILE_DIR` с путем к профилю, который был запущен с этой сессией. Приложение не вводит пароль и не обходит авторизацию. Поиск клиента выполняется через кнопку «+» рядом с поиском MAX, пункт «Найти по номеру» и номер телефона клиента. Затем проверяются клиент, диалог и текст.

Журнал сессии сохраняется в `logs\session.log` каталога данных с автоматической ротацией (файл до 5 МБ, до 5 архивов). HTML-снимки страницы MAX (`logs\max-*.html`) сохраняются только при включённой переменной `MAX_SAVE_DOM_LOG=1`; при старте приложения остаются лишь 20 последних снимков, так как они содержат фрагменты авторизованного DOM. Номера телефонов и текст сообщения в журнал намеренно не записываются.

## Запуск Windows и перенос на другой компьютер

### Первый запуск из исходного кода или ZIP

1. Скачайте и установите обычный Windows Python 3.10 или новее с `pip` (при установке рекомендуется включить Python Launcher и добавление Python в `PATH`).
2. Скачайте ZIP с GitHub и распакуйте его в папку, доступную для записи.
3. Дважды щёлкните `run.bat`. Скрипт найдёт Python через `py` launcher или команду `python`, установит зависимости приложения и Chromium для Playwright в общий кэш (см. ниже), затем запустит приложение и откроет главную страницу.

Для первой настройки нужен Интернет; последующие запуски после подготовки работают офлайн. Python автоматически не скачивается и не устанавливается. ZIP не включает Python — он должен быть установлен отдельно на компьютере запуска. При работе с MAX пользователь войдёт в свою учётную запись MAX в открывшемся браузере; авторизованная сессия не копируется в архив.

База контактов, журналы и профиль браузера MAX хранятся **вне папки приложения**, в каталоге данных `%LOCALAPPDATA%\MAX-Rassylki` (можно изменить переменной `MAX_DATA_DIR`). На новом компьютере приложение начнёт работу с чистой базой. Для переноса контактов на другой ПК скопируйте `fotomaniabot.db` из каталога данных (при остановленном backend) либо используйте экспорт/импорт приложения. Не передавайте базы и профиль MAX посторонним: они могут содержать личные данные и авторизованную сессию.

### Обновление на новую версию

Скачайте новый ZIP, распакуйте в **любую** папку и запустите `run.bat` — старую папку можно удалить.

- **База не пересоздаётся.** Данные лежат в каталоге данных и подхватываются автоматически; схема обновляется миграциями. Если в базе есть данные и нужны миграции, перед обновлением в `backups` создаётся копия (хранятся 5 последних). Для отката остановите приложение и подставьте копию вместо `fotomaniabot.db`.
- **Зависимости не скачиваются заново**, пока не изменился `backend\requirements.txt` или версия Python: они лежат в каталоге данных в `runtime\py<версия>-<хэш>` и общие для всех версий приложения. Chromium (`ms-playwright`) скачивается только при смене версии Playwright. Две последние папки `runtime` сохраняются для отката, остальные удаляются.
- **Старая копия на порту 8000.** Если приложение из другой папки ещё запущено, `run.bat` остановит его и запустит новую версию. Если остановить не удалось (копия запущена вручную), закройте её окно backend или запустите её `stop.bat`.
- **Данные от более новой версии.** Если база создана более новой версией, а запущена старая, приложение откажется стартовать и ничего не изменит: запустите свежую версию или восстановите копию из `backups`.
- **Первое обновление со старой схемы хранения.** База из `backend\fotomaniabot.db` и профиль `.max-browser-profile` копируются в каталог данных один раз при первом запуске; исходные файлы базы остаются на месте, их можно удалить вручную.

Node.js и npm не требуются: интерфейс встроен в backend и открывается из одного локального сервера. Используйте `stop.bat`, чтобы остановить запущенный backend.

API и Swagger доступны на `http://127.0.0.1:8000/docs`. Сервер слушает только локальный компьютер.

## Возможности

- локальная SQLite-база и API FastAPI;
- понятный интерфейс с разделами «Обзор», «Школы и классы», «Контакты», «Импорт», «Рассылки», «Задания» и «Настройки»;
- адресация разделов через `#hash`: ссылку на раздел или конкретную рассылку можно переслать, кнопка «Назад» в браузере работает;
- живой поиск и фильтры: контакты по ФИО/школе/классу/роли/согласию, рассылки по названию и статусу, задания по статусу, роли и школе;
- карточка задания с готовым текстом сообщения, идентификаторами MAX, историей действий и полем примечания к результату;
- массовая подготовка черновиков и открытие чатов с подтверждением и итоговой сводкой по ошибкам;
- тёмная тема, размер страницы, интервал автообновления заданий и горячая клавиша `/` для поиска; настройки хранятся в браузере;
- модель данных «школа → класс → КР и РК», где КР и РК являются отдельными контактами;
- клиенты с поиском, фильтрацией, добавлением и удалением;
- импорт CSV/XLSX с предпросмотром, сопоставлением столбцов и обработкой дубликатов; формулы не исполняются (`data_only=True`);
- персонализация `{name}` и пользовательских полей;
- черновики кампаний, запуск, очередь, сохранение состояния;
- ручные кампании с `REQUIRES_REVIEW`, подготовкой текста в MAX и подтверждением результата оператором;
- ручное управление рассылками и CSV-отчёты;
- поиск строки заголовков не только в первой строке файла;
- отдельные кампании для выбранной школы;
- ручные задания с быстрым открытием чата, фиксацией открытия ссылки и обязательным подтверждением результата;
- подготовка сообщения в уже авторизованной вкладке MAX через CDP без автоматической отправки;
- статусы заданий «Контакт не найден» и «Ошибка MAX» вместо постоянного накопления текстовых ошибок;
- редактирование и удаление школ и классов; контакты можно создавать, редактировать и удалять;
- иерархический просмотр «школа → класс → контакты» с раскрывающимися списками;
- каскадное удаление: удаление школы удаляет её классы и контакты, удаление класса — его контакты;
- локальный режим прослушивания `127.0.0.1`.

## Формат таблицы школы

При импорте выберите или введите школу, затем сопоставьте столбцы таблицы:

| Обязательное поле | Назначение |
|---|---|
| `класс` | Например, `5А` |
| `фио КР` | ФИО красного руководителя |
| `телефон КР` | Телефон КР |
| `фио РК` | ФИО родительского комитета |
| `телефон РК` | Телефон РК |

Приложение само определяет столбцы по названиям и распространённым вариантам (`Класс`, `класс`, `ФИО КР`, `КР ФИО`, `Телефон РК` и т. п.). На шаге предпросмотра автоматически найденные поля помечаются как «определено». Если название нестандартное или поле не найдено, его можно один раз выбрать вручную. Одна строка создаёт или обновляет два отдельных контакта: КР и РК. При повторном импорте для той же школы и класса можно пропустить существующие контакты или обновить их.

Сообщения для КР и РК задаются отдельно в разделе «Новая рассылка». Контакты отказавшиеся от связи исключаются из запуска.

## Ручная рассылка

Выберите одну или несколько школ, затем отметьте нужных получателей или используйте «Выбрать всех получателей». Рассылка сразу появляется под формой создания. В разделе «Контакты КР/РК» контакты можно отметить чекбоксами и удалить кнопкой «Удалить выделенные»; связанные задания удаляются вместе с контактами. Для каждого задания приложение показывает школу, класс, роль контакта и действия MAX. Кнопка «Открыть чат» выполняет поиск контакта по номеру и открывает диалог без вставки сообщения. Кнопка «Подготовить в MAX» выполняет поиск и вставку текста, но не нажимает отправку. Кнопка «Создать черновики для всех» последовательно обрабатывает только задания выбранной рассылки: открывает чат, вставляет и проверяет текст, затем переходит к следующему контакту. Если MAX сообщает, что номер не найден, уведомление закрывается перед продолжением, а задание получает статус «Контакт не найден». Отправка не выполняется; отдельная ошибка не запускает повтор и не останавливает остальные задания. После действия в MAX оператор обязан выбрать результат («Отправлено», «Не отправлено» или «Неизвестно») и нажать подтверждение. Рассылку можно удалить вместе со всеми её заданиями.

Ссылка на чат не требуется для действий MAX: поиск выполняется по номеру телефона в авторизованном интерфейсе. Поле ссылки может сохраняться в данных контакта для совместимости, но кнопки MAX используют именно поиск по номеру.

### Несколько сообщений в одной рассылке

В форме «Новая рассылка» для КР и РК отдельно выбирается количество сообщений (от 1 до 5) — появляется нужное число полей. Если заполнены не все выбранные поля, рассылка не создаётся; пустая роль (все поля пусты) просто не используется, а её получатели получают тексты другой роли. Введённые тексты не пропадают, если уменьшить, а затем снова увеличить количество.

У каждого получателя в таблице и в карточке задания появляется кнопка подготовки на каждое сообщение: «Подготовить в MAX 1», «Подготовить в MAX 2» и т. д. (отметка ✓ — черновик уже подготовлен). Каждая подготовка **заменяет** текст в поле ввода чата, поэтому сначала отправьте предыдущее сообщение вручную, затем готовьте следующее. Над таблицей можно выбрать номер сообщения для «Создать черновики для всех». Тексты можно менять по одному («Изменить текст» у нужного сообщения) или для всей рассылки («Изменить тексты», там же меняется количество сообщений; отметки подготовки сохраняются только у неизменённых текстов). В MAX одновременно выполняется одна операция — параллельный запрос получит ответ «В MAX ещё выполняется другая операция». Итог отправки подтверждается один раз на получателя, в CSV-отчёте добавлен столбец «Сообщений подготовлено».

### Карточка задания

Слева выберите получателя — справа откроется карточка с готовым текстом (уже с подставленным ФИО), телефоном, `max_user_id`, именем пользователя и ссылкой на чат. Там же видна история: когда чат открыт, когда подготовлен черновик, когда сохранён результат. Кнопка «Копировать текст» кладёт сообщение в буфер обмена — удобно, если чат открывают в другом клиенте. Примечание к результату сохраняется в задании и попадает в CSV-отчёт.

Над таблицей заданий есть полоса прогресса, чипы по статусам (клик — фильтр), поиск по ФИО и телефону, фильтр по роли и сортировка. Автообновление включено по умолчанию (интервал меняется в «Настройках», переключатель — в шапке заданий) и не перетирает открытые формы и прокрутку.

### Работа с контактами

Раздел «Контакты КР/РК» поддерживает серверный поиск, фильтры по школе, классу, роли и согласию, постраничный вывод и массовое удаление. Кнопка «Скачать CSV» выгружает выделенные контакты или весь отфильтрованный список (UTF-8 с BOM, безопасно для Excel). Добавление и изменение контакта выполняются в диалоговом окне с проверкой полей: ФИО, роль, школа и класс обязательны, телефон — не менее 10 цифр, дополнительные поля задаются в формате JSON.

### Сворачивание школ

Везде, где встречаются школы (раздел «Школы и классы» и выбор получателей рассылки), карточки сворачиваются: клик по стрелке или названию школы скрывает содержимое, оставляя в шапке счётчики классов, КР, РК и уже выбранных получателей. Внутри школы отдельно сворачивается каждый класс. Кнопки «Свернуть все» / «Развернуть все» работают на весь список, а поиск автоматически раскрывает найденные школы и классы. Состояние запоминается в браузере — при следующем открытии интерфейс выглядит так же компактно.


## Структура проекта

```
backend/
  app/
    db.py          — engine, SessionLocal, PRAGMA foreign_keys=ON, session_scope()
    message_sets.py — наборы сообщений рассылки и задания (несколько текстов на роль)
    models.py      — единственное описание ORM-моделей (Base, Client, Campaign, ...)
    schemas.py     — Pydantic-схемы запросов
    services.py    — рендер сообщений, CSV-экранирование, разбор заголовков
    migrations.py  — упорядоченные миграции SQLite
    max_browser/   — работа с уже авторизованной вкладкой MAX через CDP: connection (одно
                     переиспользуемое подключение), page, search, editor, chat, rename
    main.py        — сборка приложения FastAPI, логирование, lifespan, статика
    worker.py      — фоновый воркер очереди заданий
    routers/       — маршруты по разделам: schools, clients, campaigns, imports,
                     tasks, reports
    static/        — интерфейс оператора: index.html, styles.css, js/*.js (ES-модули, без сборки)
  tests/           — pytest: API и чистые функции
  run.py           — запуск uvicorn с настройками из окружения
```

Схема данных описана один раз в `models.py`; приложение применяет её и миграции
при старте (идемпотентно). Внешние ключи SQLite включены, поэтому каскадное
удаление работает на уровне базы.

## Настройки окружения

Все переменные окружения необязательны (файл `.env` приложением не читается — задавайте их в окружении процесса). Основные: `DATABASE_URL`, `APP_HOST`, `APP_PORT`, `APP_RELOAD`,
`MAX_CDP_URL`, `MAX_BROWSER_PROFILE_DIR`, `MAX_SAVE_DOM_LOG`.

## Разработка

```bat
cd backend
..\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
..\.venv\Scripts\python.exe -m pytest
..\.venv\Scripts\python.exe -m ruff check app tests
```

## Данные

База находится в каталоге данных: `%LOCALAPPDATA%\MAX-Rassylki\fotomaniabot.db`. База работает в режиме WAL (рядом могут появляться файлы `fotomaniabot.db-wal` и `-shm`). Перед ручным копированием остановите backend — при остановке содержимое сливается в основной файл — и скопируйте `fotomaniabot.db`. Не помещайте пароли или токены в репозиторий.
